This file describes special data formats used in the project.

*** common.dat ***

Purpose - contains **Event record** bundle (location-independent)
Created by:
	common_create.pl (gathering into single file) - invoked by build.xml
Used in:
	Datafile.java - checking header, loading common data
	
Header fields:
	0x0000	short LB	year
	0x0002	byte		month
	0x0003	byte		day
	0x0004	byte		hour
	0x0005	byte		minute ^ start of period
	0x0006	short LB	days in period
	0x0007  ...			see **Event record**

*** Event record ***

Purpose - holds specific type of events that occur during the year.
Created by:
	mutter2/mutter (event calculation)
Used in:
	Datafile.java - retrieving events
	mutter2/mutter - event dumping

Header fields:
	0x0000	byte		next digit of IMEI, if applicable
	0x0001	byte		event type (defined in Event.java)
	0x0002	short LB	data length (used to skip a record)
	0x0004	short LB	event flags
	0x0006	byte		planet
	...					<event data> depend on flags

*** locations.dat ***

Purpose - contains **Event record** bundle (location-dependent)
Created by:
	locations_create.pl (gathering into single file) - invoked by build.xml
Used in:
	GeoList.java - checking header, loading common data
	
Header fields:
	0x0000	short LB	year
	0x0002	short LB	record count in bundle
	0x0004	short LB	<location data length array>
	...					see **Loc record**

*** Loc record ***

Purpose - contains **Event record** bundle for a certain city.
Created by:
	geoCoord.pl (event calculation)
Used in:
	Datafile.java - retrieving events

Header fields:
	0x0000	short LB	year
	0x0002	byte		month
	0x0003	byte		day
	0x0004	byte		hour
	0x0005	byte		minute ^ start of period
	0x0006	short LB	days in period
	0x0008	short LB	city name length
	0x000a	UTF-8		city name
## TODO: these fields may result in illegal calculations!!!
			short LB	timezone offset. DST is applicable if 15th bit is set.
						Real TZofs=(tz-16*60)*60000 msec.
			short LB	DST start date, if applicable (local time)
			short LB	DST end date, if applicable (local time)
	
*** data/*.ini ***

Purpose - contains location sets to be calculated and loaded into DB.
Created by:
	manually
Used in:
	geoCoord.pl - generating datafiles by mutter2/mutter

Hints:
    The main problem is to write correct names of city, its state (if applicable)
    and country. User has to provide alternative names in order to query
    correct coords from coords.sqb database and timezone info from city.txt.
@ country in COORDS$country, [state]
    city name in COORDS!city name in city.txt

    In case if city is a capital of state or country and contains non-ASCII letters,
    its name must be corrected in tz_patches.pm.
    If it is an ordinary city, it must be included into add_city.txt, under appropriate country

    Country name should not contain braces.

*** data/archive/*.ini ***

Purpose - contains location coords in form: city|lon|lat|country [- state]|continent [|altitude].
Created by:
	geoCoord.pl
Used in:
	geoCoord.pl - generating datafiles by mutter2/mutter
Hints:
    Altitude is optional (default 0). If city field of *.ini begins with '-', the rest of line is copied into
    data/archive/*.txt unchanged. Now the ancient places only are entered in such a way.

Continent keys:
    ANC - Ancient places (either mystic or somewhat sanctuary)
    AFR - Africa
    EAS - East Asia
    SAS - South Asia
    SEA - Southeast Asia
    CAR - Caribbean
    CAM - Central America
    EUR - Europe
    EEU - Eastern Europe
    WEE - Western Europe, Skandinavia, and UK
    MIE - Middle East
    NAM - North America
    OCE - Oceania (Australia/New Zealand)
    SAM - South America


Errors while running:
    1 - 1st getstr failed - invalid message langfile
    6 - options.resetStorage failed again
    11 - ambuiquity when creating RMS (device-specific), see GeoList.initDB().
        This shouldn't occur at mobile device, only at emulator.
    1501 - in Summary when getting Sun day - RMS contains invalid location file
        of different year etc. This shouldn't occur at mobile device, only at
        WTK.
